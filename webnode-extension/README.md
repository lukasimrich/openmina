# OpenMina Chrome Extension MVP

## Phase 1: Testing Cross-Origin Isolation ✅ COMPLETED

### Loading the Extension

1. Open Chrome and navigate to `chrome://extensions/`
2. Enable "Developer mode" in the top right
3. Click "Load unpacked" and select the `webnode-extension` directory
4. The extension should appear in the extensions list

### Testing Cross-Origin Isolation

1. Click the OpenMina extension icon in the toolbar to open the sidebar
2. Open Chrome DevTools (F12)
3. Check the Console tab for messages from the offscreen document
4. Look for either:
    - ✅ "SUCCESS: Offscreen document IS cross-origin isolated"
    - ❌ "CRITICAL FAILURE: Offscreen document IS NOT cross-origin isolated"

## Phase 2: Testing Bundled WASM Loading 🚀 READY FOR TESTING

### Prerequisites

-   Phase 1 must be working (cross-origin isolation confirmed)
-   Extension should be loaded and showing "Status: Offscreen ready & isolated."

### Testing Bundled WASM Initialization

1. With the extension loaded and sidebar open, click "Initialize Node"
2. Open Chrome DevTools (F12) and monitor the Console tab
3. Look for the following sequence of messages:
    - "Offscreen: Received INIT_WASM_IN_OFFSCREEN. Calling initializeWasmNode() for bundled WASM."
    - "Bundled WASM script injected, waiting for initialization..."
    - "OpenMina bundled module: Starting initialization..."
    - "OpenMina bundled module: WASM initialized successfully"
    - "OpenMina bundled module: Node started successfully"
    - "OpenMina bundled module initialized successfully"

### Expected Behavior

-   ✅ **Success**: Sidebar shows "Status: WASM bundled module loaded" or node status JSON
-   ✅ **Threading**: No "unreachable" errors or threading failures
-   ✅ **Bundling**: All imports resolved without dynamic import errors
-   ❌ **Failure**: Any CSP violations, import resolution errors, or threading issues

### Troubleshooting

-   **CSP Errors**: ✅ Fixed! Added `'wasm-unsafe-eval'` to manifest.json CSP
-   **Import Errors**: Verify all snippets are bundled correctly
-   **Threading Errors**: Confirm cross-origin isolation is working
-   **WASM Load Errors**: Check that bundle.js and .wasm files are accessible

### Common Issues & Solutions

1. **"Refused to compile WebAssembly module"**:

    - ✅ **FIXED**: Added `content_security_policy` with `'wasm-unsafe-eval'` to manifest.json
    - Reload the extension after this change

2. **Dynamic import errors**:

    - Ensure all snippets are bundled with Rollup
    - Check that `dist/bundle.js` contains all dependencies

3. **Threading failures**:
    - Verify cross-origin isolation is working (`self.crossOriginIsolated === true`)
    - Check COOP/COEP headers in manifest and offscreen.html

## File Structure

```
webnode-extension/
├── manifest.json          # Extension manifest with COOP/COEP
├── sidebar.html           # Sidebar UI
├── sidebar.js             # Sidebar logic
├── background.js          # Service worker
├── offscreen.html         # Offscreen document with COI headers
├── offscreen.js           # Phase 2: Bundled WASM loading
├── index.js               # Bundling entry point
├── rollup.config.js       # Rollup bundling configuration
├── package.json           # NPM dependencies
├── dist/
│   ├── bundle.js          # Bundled ES module (WASM + JS + snippets)
│   └── openmina_node_web_bg.wasm  # WASM binary
├── pkg/                   # Generated by wasm-bindgen
│   ├── openmina_node_web.js       # JS glue code
│   ├── openmina_node_web_bg.wasm  # WASM binary
│   └── snippets/          # wasm-bindgen snippets
└── README.md             # This file
```

## Build Process

To rebuild the bundled WASM module:

1. Compile WASM: `cargo build --release --target wasm32-unknown-unknown -p openmina-node-web`
2. Generate bindings: `wasm-bindgen --target web --out-dir pkg ./target/wasm32-unknown-unknown/release/openmina_node_web.wasm`
3. Bundle everything: `npx rollup -c`
4. Copy WASM: `cp pkg/openmina_node_web_bg.wasm dist/`
